# Contributing

Contributions are always welcome!

## How Can You Contribute?

* [By submitting a bug report or a feature request](#bug-reports-and-feature-requests)
* [By translating the app](#translations)
* [By submitting code improvements](#code-contributions)

## Bug Reports and Feature Requests

If you find a bug or have an idea for a new feature,
please [submit an issue](https://codeberg.org/Patkek/ASComplete/issues).

When reporting a bug, include as much relevant information as possible, such as:

- A clear description of the problem
- The steps needed to reproduce it
- What you expected to happen
- What actually happened
- Your android version
- The ASComplete version you are using
- Relevant error messages, logs, or screenshots

For feature requests, explain:

- What feature you would like to see
- Why it would be useful
- How you would expect it to work
- Any alternatives or workarounds you currently use

Before submitting an issue, please search the existing issues to make sure the bug or feature has
not already been reported. Use a clear and descriptive title, and provide enough detail for others
to understand and reproduce the issue.

## Translations

ASComplete translations are handled
on [Codeberg Translate](https://translate.codeberg.org/projects/ascomplete/)

## Code Contributions

Code contributions are welcome. To contribute code:

1. Check the existing issues to find a bug or feature you would like to work on.
2. If no relevant issue exists, open one first to discuss your proposed changes.
3. Fork the repository and create a new branch for your work.
4. Make your changes while following the project’s existing coding style.
5. Test your changes to make sure they work as expected.
6. Commit your changes with a clear and descriptive message.
7. Push your branch and open a pull request.

In your pull request, explain:

- What you changed
- Why you made the change
- How you tested it
- Any issues or limitations that reviewers should know about

Please keep pull requests focused on a single bug fix or feature whenever possible. Small, focused
changes are easier to review and merge.
